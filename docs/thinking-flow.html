1. Source-first intake, local parsing & safety boundary

The Engine still begins with the evidence itself. Files are parsed locally, screened, registered with stable provenance, and converted into redacted bounded packets before any governance inference is permitted.

Evidence boundary first · live
Critical trust idea: uploaded material is untrusted evidence, never executable instruction. Raw bytes remain outside the reasoning contract. Provider packets carry deterministic summaries and the user-approved Intake — not source text, code, cells, pixels, names or quotes.

Open scope note
The original presentation described the intended architecture. That architecture is implemented. This snapshot does not replace it. It marks what is live, what is loaded and waiting, and the one remaining knowledge gap, so the visual can be used as a status document rather than only as a design pitch.

What the original got right

  • Eight-stage evidence-gated flow, not a free-form reviewer
  • User-confirmed Intake before analysis
  • Independent verification before finding lock
  • Deterministic hard gates, readiness and publication as separate authorities
  • Exact tactic mapping from locked findings — not keyword search
  • Humans retain formal governance authority

What this snapshot corrects

  • Knowledge is split: Playbook APPROVED, assessment objects NOT_PUBLISHED — not a single “approved runtime Knowledge Base”
  • Run state is not only process-local: optional PostgreSQL durable-run-state-1.0.0 exists; raw evidence remains process-local by design
  • Image pixels are never sent to providers; multimodal is explicitly skipped
  • Empty playbook after thin evidence is expected; gaps are not locked findings
  • Calibration / test-only product language is removed

Still live in the Engine

  • Structured-output stages for solution understanding, routing, A–F claims, verification, rescan, adjudication, synthesis and fact-check
  • Fixed three-role provider routing with independent-provider constraints
  • Privacy-safe packets, packet-hash binding, live Intake cache retention
  • Coverage matrix, finding lock, action grounding, publication gate

Current remaining boundary

  • Only knowledge gap: author the 30 capability / anti-pattern pairs, compile --release-status APPROVED, publish the Vercel manifest
  • Authentication, tenant authorization, horizontal scaling and production monitoring remain hardening work
  • Without a database, restarts lose in-memory runs; with one, pre-approval recovery still requires re-upload
  • Images rely on caller-provided sanitized metadata
