## 1. What this repository is & Space / sibling boundaries
- **Browser UI & Static Assets (`public/`):** Vanilla ES module SPA (`public/index.html`, `public/app.js`, `public/report.js`, `public/documentation-handoff.js`, `public/content-policy.js`, `public/styles.css`). Drives source-first Intake, the **Assessment Workspace**, and the **Assurance Summary** (plus offline, script-free downloadable HTML and printable views) strictly from the canonical JSON readiness package without calculating a second outcome.
- **Governed HTTP API, Local Acquisition Lanes & Deterministic Core (`src/`):** Node.js ESM (`>=20.16.0`; Node 22 in CI/Cloud, `pnpm@10.34.5`) HTTP service (`src/server.js`, default port `4174`) packaged for Railway (`railway.json`). Runs local DLP/source screening and versioned document, OCR, HTML, code/configuration, tabular, and media-summary lanes (`src/intake/`, `src/core/`), enforces the user-approved Intake snapshot boundary (`src/cognitive/preflight.js`), executes cognitive contract `3.1.0` across `WORKHORSE`, `REASONER`, and `QUALITY_CHECKER` (`src/cognitive/`), and computes deterministic A–F governance domains across seven lifecycle stages, hard gates, and readiness recommendations (`src/engine.js`, `src/core/`).
- **Persistence & Runtime Knowledge (`db/`, `knowledge-authoring/`):** Optional PostgreSQL safe-checkpoint and expiring-lease store (`db/migrations/001_governance_runs.sql` via `DATABASE_URL`; in-memory `EphemeralRunStore` when unset). Loads either a hash-pinned remote runtime manifest (`VERCEL_KB_MANIFEST_URL`, optional `BLOB_READ_WRITE_TOKEN`) or the bundled local unpublished snapshot (30 capability/anti-pattern pairs with 180 questions plus 119 approved Playbook tactics in `knowledge-authoring/catalog/`).
- **Space & sibling solution boundaries:**
  - **Single-repository development:** Develop this solution from the **Solution Assurance Engine** Space (`jorieskolin-creator/AI-Governance-Engine` only). Do not read or edit sibling repositories during Engine tasks unless the owner explicitly asks to evaluate or align cross-repository contracts (for which **Jocce's Factory** serves as the shared multi-repository verification environment).
  - **Upstream sibling — Solution Assurance Documentation Support (`jorieskolin-creator/solution-assurance-documentation-support`):** Produces optional inert HTML (`<script id="doc-support-handoff" type="application/json">`) or standalone JSON exports under `doc-support-handoff/1.0.0` (embedding `failure-mode-register/1.0.0`), ingested via `public/documentation-handoff.js` and `src/intake/documentation-input.js` into `declared-documentation/1.0.0`. Handoffs are **declaration-only (`evidenceCeiling: "DECLARED"`)**: they prioritize draft Intake fields (`name`, `purpose`, `current-stage`, `users`, `excluded-uses`) and provide failure-mode context, never authenticate the author, never follow external reference paths, never count `NOT_RUN` as evidence, and still require at least one independent parsed source plus separate accountable-owner confirmation. Highlight any proposed change to `doc-support-handoff/1.0.0` or `failure-mode-register/1.0.0` before proceeding so both solutions stay synchronized.
  - **Upstream producer — Knowledge Base Maintainer / Creator (`jorieskolin-creator/AI-Governance-KB-Maintainer-Tool`):** Separate producer of immutable runtime collection JSON and `runtime-manifest.json` (`schemaVersion: "1.1.0"`). Never import producer source code or share databases/process state; this Engine consumes published manifests strictly via hash-verified HTTP (`docs/knowledge-base.md`).

## 3. Verification commands
Run all checks relevant to your change before pushing or opening a PR:

- **Install locked dependencies (Node `>=20.16.0`, Node 22 in CI; `pnpm@10.34.5`):** `pnpm install --frozen-lockfile`
- **Full CI verification gate (JS syntax + FinOps-residue source check + restricted-identifier content policy + full `node --test` suite):** `pnpm run check`
  *(Run `pnpm run check` **after** staging new or modified files with `git add`, because `scripts/check-content-policy.js` scans `git ls-files` across code, `.md`, JSON, HTML, DOCX, and PDF artifacts.)*

Never run `BENCHMARK_CONFIRM_LIVE_CALLS=true pnpm run benchmark:models` or `pnpm run kb:verify-runtime` against live paid provider APIs or live Blob URLs without explicit owner authorization.

## 4. Non-negotiable invariants
- **Raw source material stays process-local; provider packets are privacy-safe summaries only.** Raw documents, source code, configuration, archives, spreadsheet headers/cells/values, unrestricted OCR text, and image pixels never enter provider requests or PostgreSQL (`durable-run-state-1.0.0`) and are purged at cognitive queue admission after final Intake approval. Provider packets accept only schema-validated deterministic summaries, controlled `semantic-intake-evidence-1.0.0` observations, hash-bound `acquired-fact-selection-1.0.0` Boolean/enum selections, and the user-approved canonical Intake. Media egress fails closed (`LOCAL_MEDIA_SUMMARIES_ONLY`).
- **User-only Intake authority.** Deterministic discovery, `WORKHORSE` retrieval plans (`intake-retrieval-plan-1.1.0`), local bounded re-reads (`local-bounded-reread-1.0.0`), `REASONER` missing-field proposals, and Intake wording assistance are strictly advisory/editable. Only explicit user confirmation (`POST /api/v2/runs/{id}/confirm`) creates `approved-intake-snapshot-1.3.0` and authorizes analysis; `POST /api/assess` remains retired (HTTP 410).
- **Models author bounded semantics; code owns applicability, assurance, anti-pattern state, hard gates, readiness, hashes, and authority.** Only independently verified, adjudicated claims become locked findings. Missing evidence stays `UNKNOWN` (silence never proves safety, compliance, or absence of an anti-pattern). Code/configuration establishes at most `IMPLEMENTED` (lexical matches are `AUTOMATED_INDICATOR` only); scoped passing test records are required for `TESTED`, and operational records for `OPERATIONALLY_OBSERVED`. Hard gates are non-averagable and cannot be overridden by scores or narrative synthesis.
- **Formal human authority is unreachable by Engine output.** Readiness outcomes (`READY_WITH_CONDITIONS`, `REMEDIATE_BEFORE_NEXT_STAGE`, `HUMAN_REVIEW_REQUIRED`, `BLOCKED_IN_CURRENT_FORM`) are recommendations only. `HUMAN_VALIDATED` requires a non-engine actor and allow-listed human authority; `FORMALLY_APPROVED` is unreachable through the public assessment API.
- **Independent three-provider topology & fail-closed execution.** Governance routing requires independent providers across assessor (`WORKHORSE`), verifier (`QUALITY_CHECKER`), and adjudicator (`REASONER`). Eligible provider failures may advance once to configured, provider-independent fallbacks; cancellation, lease loss, Engine budget exhaustion, and interrupted active runs (`RECOVERY_REQUIRES_USER_RESTART`) never auto-replay or switch providers.
- **Customer evidence vs. Knowledge Base & FinOps separation.** Knowledge Base objects and Tactic Playbook entries are governance criteria/remediation patterns, never case evidence, and tactic completion (`NEW_EVIDENCE_AND_REASSESSMENT_REQUIRED`) never closes a finding. Keep zero FinOps-domain semantic residue in Engine code (`scripts/check-sources.js` enforces forbidden terms).
- **Restricted-identifier & content-free operational logging.** Never introduce restricted identifiers (`public/content-policy.js` / `scripts/check-content-policy.js`). Keep structured stdout JSON logs strictly content-free (normalized routes, opaque `requestId`/`runId`, stable `failureCode`, stages, durations, and aggregate counts — never source paths/content, request bodies, prompts, provider responses, credentials, or IP addresses).
- **Idempotent, backward-safe SQL migrations.** Do not break applied schema contracts in `db/migrations/001_governance_runs.sql`; introduce schema evolution via clean, idempotent migrations and keep tests offline.

## 5. Data, secrets, deployment, and test isolation
- Keep `pnpm test` and `pnpm run check` completely offline using synthetic local fixtures, injected transports, and fake database pools; never call live OpenAI, Anthropic, Google, xAI, or Moonshot APIs or read/write live Railway PostgreSQL or Vercel Blob storage during tests.
- Never read, print, hardcode, or commit `.env` or secret values (`ADMIN_SECRET`, `OPENAI_API_KEY`, `GPT_API_KEY`, `ANTHROPIC_API_KEY`, `GEMINI_API_KEY`, `GOOGLE_API_KEY`, `XAI_API_KEY`, `MOONSHOT_API_KEY`, `DATABASE_URL`, `BLOB_READ_WRITE_TOKEN`, or Railway tokens). Keep `.env.example` placeholder-only (`scripts/check-sources.js` requires `.env.example` to exist).
- Do not modify `railway.json`, deploy to Railway, set placeholder URLs on `VERCEL_KB_MANIFEST_URL` (a configured URL is fail-closed at startup), or mutate live Vercel Blob storage unless explicitly requested and approved by the owner.
